# 端到端工作流

## 总原则

工作流以“证据成熟度”而非写作进度推进。任何阶段都不得静默补造上游缺失信息。可并行开展代码、图表和文字，但进入下一门槛前必须汇合到同一组版本化结果。

## S0：建立约束基线

读取赛题、附件、结果模板、官方格式和仓库规则，输出事实清单：问题目标、输入、输出、单位、精度、提交文件、页数或匿名要求、截止时间。逐条注明来源。历史论文排版只能作为无冲突时的默认值。

门槛：每个必交结果和格式要求都有来源；冲突项显式列出。

## S1：构建问题图

把各问画成依赖图，区分基线问、扩展问、优化问和验证问。为每问填写：

```text
Question:
Objective:
Inputs:
Required outputs:
Inherited model/results:
New variables:
New assumptions:
Candidate model:
Fallback model:
Validation evidence:
Failure condition:
```

门槛：后一问继承什么、改变什么、额外求什么都清楚。

## S2：数据与符号审计

建立数据字典和符号表。检查字段、单位、缺失、重复、时间或空间覆盖、异常值、模板结构。原始数据保持只读。符号表至少包含符号、含义、单位、定义域或索引；一符一义，同义变量只保留一个。

门槛：程序字段、公式符号和论文表述一一对应。

## S3：建立模型合同

先写最小闭合模型，再决定复杂扩展。模型合同包括：

$$
\begin{aligned}
&\text{状态或决策变量：} && \boldsymbol{x},\ \boldsymbol{u},\\
&\text{模型：} && \mathcal{F}(\boldsymbol{x},\boldsymbol{u};\boldsymbol{\theta})=0,\\
&\text{目标：} && \min_{\boldsymbol{u}} J(\boldsymbol{x},\boldsymbol{u}),\\
&\text{约束：} && \boldsymbol{g}(\boldsymbol{x},\boldsymbol{u})\le 0,\quad
\boldsymbol{h}(\boldsymbol{x},\boldsymbol{u})=0.
\end{aligned}
$$

记录参数来源、初始/边界条件、量纲、可识别性、简化理由和潜在失效区间。复杂模型必须保留可比较的基线。

门槛：模型闭合、量纲一致、输入足以产生题目要求的输出。

## S4：数值实现与最小试跑

正式逻辑写入可复现脚本，不把 Notebook 当唯一实现。集中配置参数，固定随机种子，记录语言和依赖版本。先运行小规模算例，检查边界、极限情形、非负性、单调性或守恒等不变量。

门槛：从项目根目录可运行；输入输出路径稳定；最小算例通过。

## S5：求解、优化与验证

按模型类型选择验证组合：解析解或简化解对照、数值收敛、拟合残差、留出样本、物理量纲和极限、守恒残差、重复随机种子、基准方法、可行性、敏感性与稳健性。

优化模型至少报告：目标函数值、决策变量、约束余量、搜索域、算法参数、停止准则、随机种子、重复运行离散度。启发式算法不能仅给“最优解”。

门槛：每条主结论都有命名证据；所有必需约束满足。

## S6：冻结证据包

为每问建立结果卡：

```text
Claim:
Exact value and unit:
Source file and field:
Figure/table:
Validation:
Allowed wording:
Forbidden stronger wording:
Uncertainty or limitation:
```

同时冻结机器可读结果、论文表、论文图和生成脚本的版本。快速试跑结果不得进入论文。

门槛：正文所需的全部数值可以追溯到结果文件。

## S7：按证据写正文

先写各问的模型与结果，再写问题分析、假设、符号、评价，最后写摘要、关键词和标题。每问采用“准备—建立—求解—结果—检验”的紧凑闭环；若某环节不适用，说明原因而非机械补标题。

门槛：公式、图、表和结论均有正文引用；摘要数值与正文一致。

## S8：图表与版式

为每张图建立图表合同：一句话结论、数据来源、横纵轴与单位、图例、误差含义、输出尺寸、正文引用位置。应用当年官方模板；无明确模板时再采用历史获奖论文的保守默认版式。

门槛：缩放到最终版面后仍可读；无装饰图、重复图或截图式表格。

## S9：三轮审查

1. 数值审查：重新生成关键结果，核对单位、精度、约束、随机性和表格。
2. 全文审查：执行主张审计、符号审计、编号和交叉引用审计、引用审计。
3. PDF 审查：编译、逐页渲染，检查字体、公式、分页、图表、页码、匿名信息和附件清单。

门槛：阻断项为零；重大项均有处理结论。

## S10：提交包封存

按仓库命名规范生成版本化提交包和清单。记录源代码版本、运行命令、依赖版本、随机种子、结果文件哈希或时间戳。不要使用“最终版”“最新版”等模糊名称。
